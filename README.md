# Telegram — пульт

## Как это работает

Панель разговаривает с Telegram **напрямую его родным протоколом** (MTProto,
библиотека Telethon) — так же, как это делает телефон или Telegram Desktop.
Браузер для работы больше не нужен: ни окна, ни кликов по вёрстке, ни ожиданий
по полторы секунды. Отсюда всё остальное:

- проверка номера занимает секунды, а не полминуты;
- ничего не ломается от того, что Telegram поменял разметку сайта;
- аккаунт виден Telegram как обычный десктоп, а не как веб-сессия.

Взамен появляется одно жёсткое требование: **до дата-центров Telegram должен
быть доступ**. Веб-версия у многих провайдеров открывается, а MTProto режется —
тогда нужен VPN или прокси, который пропускает именно Telegram (проверить:
кнопка «Проверить IP» в панели). Прокси, через который открывается любой сайт,
но не проходит Telegram, для панели бесполезен, и панель об этом прямо скажет.

Старые скрипты через браузер (`*.mjs`: `check-batch.mjs`, `draft-messages.mjs`
и прочие) остались лежать рядом — панель их больше не запускает, но при
желании их можно вызвать руками.

## Установка на новом компьютере

1. Поставить [Node.js](https://nodejs.org) (обычной установкой, один раз).
2. Распаковать эту папку себе.
3. Запустить лаунчер для своей системы:
   - **macOS** — двойной клик по **«Запустить панель.command»**.
     Если ругнётся, что файл из интернета: правый клик → «Открыть» → «Открыть».
   - **Windows** — двойной клик по **«Запустить панель.bat»**.
     Если выскочит «Windows защитила ваш компьютер»: «Подробнее» → «Выполнить в любом случае».

При первом запуске лаунчер сам доставит всё нужное и откроет панель (пара минут).

## Запуск на Windows — по шагам

Первый раз на новом компьютере:

1. **Node.js** — скачай LTS с [nodejs.org](https://nodejs.org), поставь
   обычным «Далее → Далее». Нужен всегда.
2. **Python** — с [python.org](https://python.org/downloads) (версия 3.10–3.13).
   На первом экране установщика **поставь галочку «Add Python to PATH»**, потом
   «Install Now». Python обязателен: вся работа с Telegram идёт через него
   (Telethon), плюс базы в Excel (`.xlsx`) и импорт TDATA. Без Python панель
   откроется, но проверять и писать не сможет.
3. Скопируй всю папку панели себе (например в «Документы»).
4. Двойной клик по **«Запустить панель.bat»**.
   - «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».
   - Первый запуск идёт пару минут: ставятся Python-зависимости
     (`telethon`, `python-socks`, `qrcode`, `openpyxl`, `opentele`) в папку
     `venv-tg`, а также Playwright с браузером — он нужен только старым
     скриптам и разовому переносу уже открытой сессии.
   - Спросит **логин и пароль** для входа в панель — придумай и запомни.
5. Откроется браузер на `http://localhost:8787`. Введи тот логин с паролем.

Дальше по шагам в панели: добавить аккаунт (QR или готовой сессией) → загрузить
базу → проверить → написать.

Каждый следующий запуск — просто двойной клик по тому же `.bat`. Чтобы
остановить панель, закрой чёрное окно.

**Если панель говорит, что Python не найден** — значит при установке Python не
была отмечена галочка «Add to PATH». Переустанови Python с этой галочкой (или
включи PATH вручную) и запусти `.bat` заново. Без Python панель работать
не будет: проверка и рассылка живут в нём.

**Открыть панель с телефона или другого компьютера** — см. раздел «Панель в
вебе» ниже: просто так наружу её выставлять нельзя, нужен туннель или HTTPS.

## Вход в панель

Панель закрыта логином и паролем. Задать или сменить:

```
node set-password.mjs <логин> <пароль>
```

Пароль на диск в открытом виде не пишется — только scrypt-хэш с солью
(`auth.json`). Смена пароля выкидывает из панели всех, кто уже вошёл.
Восемь неверных попыток подряд — и адрес отдыхает пять минут.

## Панель в вебе

По умолчанию панель слушает только сам компьютер (`127.0.0.1`) — снаружи
её не видно. Чтобы открыть доступ, **нужно шифрование**: по открытому HTTP
пароль уходит по сети как есть, и панель просто откажется так стартовать.

Самый простой способ — оставить панель на месте и прокинуть туннелем,
он даст и адрес, и HTTPS:

```
cloudflared tunnel --url http://localhost:8787
```

Со своим сертификатом:

```
node admin.mjs --host 0.0.0.0 --cert cert.pem --key key.pem
```

Если снаружи уже стоит nginx с HTTPS, а панель слушает только его —
`node admin.mjs --host 0.0.0.0 --insecure-http`.

Помни, что за паролем стоит доступ к твоим сессиям Telegram и к рассылке.
Пароль на панель = пароль на всё это.

## Установка на сервер

Чтобы панель работала, когда компьютер выключен, её надо поселить на сервере.

**Vercel, Netlify и прочий serverless не подойдут** — и дело не в цене. Там код
просыпается на запрос, живёт секунды и забывает всё, что записал на диск.
А панели нужно ровно обратное: жить постоянно, хранить файлы сессий Telegram,
держать очередь и брони, запускать Python-задачи на часы и гонять автопрогон,
пока никто не смотрит. Это не сайт, это служба.

Нужен обычный **VPS с Linux**. Много от него не требуется: 1–2 ГБ памяти,
10–20 ГБ диска, Ubuntu 22.04+ или Debian 12+. Это самый дешёвый тариф почти
везде, порядок цены — несколько евро в месяц. Бери площадку поближе к своей
аудитории и убедись, что с неё вообще виден Telegram.

**Что важнее выбора VPS.** С адреса дата-центра Telegram банит аккаунты
заметно охотнее, чем с домашнего или мобильного. Поэтому на сервере
**обязательно ставь аккаунтам прокси** — панель это умеет, у каждого аккаунта
свой адрес (см. «Прокси»). Без этого дешёвый сервер выйдет дорогим: потеряешь
аккаунты, а не деньги.

### Одной командой с этого компьютера

Когда у сервера есть адрес и на него пущен твой ключ SSH:

```
bash deploy/push.sh root@адрес-сервера
```

Скрипт сам отвезёт код, заведёт на сервере отдельного пользователя `tgpanel`
(службе ни к чему права root) и запустит установку. **Секреты не уезжают
никогда**: ни сессии, ни реестр аккаунтов, ни пароль от панели, ни базы. Из-за
этого же повторный запуск безопасен — обновление кода не трогает данные
сервера.

| ключ | зачем |
|---|---|
| `--key ~/.ssh/id_ed25519` | если ключ не тот, что берётся по умолчанию |
| `--port 2222` | нестандартный порт SSH |
| `--no-password` | не спрашивать вход в панель — задашь его сам (см. ниже) |
| `--code-only` | только обновить код и перезапустить службу |

Вход по паролю SSH скрипт не использует принципиально: пароли не место
в скриптах. Если ключ ещё не на сервере — `ssh-copy-id root@адрес` один раз.

**Если ставит кто-то другой** (помощник, подрядчик, ИИ-агент) — пусть добавит
`--no-password`. Тогда установка пройдёт полностью, но служба останется
выключенной и будет ждать, пока **ты сам** задашь вход:

```
cd /opt/tg-panel && sudo -u tgpanel node set-password.mjs <логин> <пароль>
sudo systemctl start tg-panel
```

Так пароль от панели не проходит ни через чужие руки, ни через переписку —
а за ним стоят живые аккаунты Telegram.

### Установка руками, на самом сервере

Скопируй папку панели на сервер — **без** `sessions/`, `accounts.json`,
`auth.json`, `numbers.csv`, `results.csv`, `drafts.csv`, `members.csv`,
`chats.json`. Это твои данные, возить их по чужим машинам незачем. Дальше
из папки панели:

```
sudo bash deploy/install.sh
```

Скрипт доставит Node и Python, соберёт окружение, спросит новый вход в панель
и заведёт службу systemd: панель поднимется сама после перезагрузки сервера и
переживёт падение. Ключи:

| ключ | зачем |
|---|---|
| `--voice` | доставить `ffmpeg` — нужен только для рассылки голосовыми |
| `--tdata` | доставить `opentele` — только ради импорта TDATA, это +300 МБ и несколько минут на сборку |
| `--port 9000` | другой порт |

Без `--tdata` панель работает полностью, просто `.zip` с TDATA не примет:
`.session`, вход по QR и вход по коду от этого не зависят. Кнопка «Открыть
в Telegram Desktop» на сервере тоже не работает — ей нужен рабочий стол.

### Как попасть в панель из браузера

Панель слушает только `127.0.0.1` — наружу её отдаёт туннель. Порт в интернет
не открывай: за паролем панели стоят живые аккаунты Telegram.

* **Cloudflare Tunnel** — бесплатно, сразу с HTTPS и адресом, дырок в файрволе
  не нужно: `cloudflared tunnel --url http://localhost:8787`. Постоянный адрес
  на своём домене — через `cloudflared tunnel login` и именованный туннель,
  он тоже живёт службой.
* **Tailscale** — если панель нужна только тебе: `tailscale up` на сервере и
  на своих устройствах, дальше `http://<имя-сервера>:8787` по частной сети.
  Публичного адреса нет вовсе — самый спокойный вариант.
* **nginx со своим сертификатом** — если он уже стоит: пусть проксирует на
  `127.0.0.1:8787`.

Команды службы: `systemctl status tg-panel`, `systemctl restart tg-panel`
(после обновления кода), `journalctl -u tg-panel -f` — журнал живьём.

### Обновить код на сервере

```
bash deploy/push.sh root@адрес-сервера --code-only
```

Уезжает только код, служба перезапускается. На месте остаётся всё, что живёт
на сервере: `accounts.json`, `sessions/`, csv-файлы, **тексты писем** и
**список прогрева** — их правят прямо в панели, и обновление кода не должно
откатывать эту правку. С кодом едет только образец `warm-list.default.json`:
если рабочего списка ещё нет, панель заведёт его из образца сама.

## Как устроена панель

Сверху вниз, в том порядке, в каком ей пользуются:

1. **Кто работает** — галочки на аккаунтах. Это **единственный выбор на всю
   панель**: всё, что ниже, делают только отмеченные. Они делят базу между
   собой, и одному человеку пишет ровно один из них.
2. **Получатели из чатов** — второй способ набрать людей, если номеров нет:
   панель обходит папку Telegram с чатами, собирает участников и кладёт их
   в ту же очередь, что и проверенные номера.
3. **Запуск** — главный блок, делает всё сам: разбирает таблицу, проверяет
   номера, пишет найденным. Внутри три понятных шага — таблица, что делать,
   скорость. Крупно видно, **черновики это или настоящая отправка**, и что
   происходит прямо сейчас («Проверяю базу · проверено 40 из 200»).
4. **Результат** — числа, ради которых всё: в базе / проверено / есть в Telegram
   / написано / **ответили**, и список ответивших с их текстом. Журнал читать
   не нужно.
5. **Что напишем** — текст сообщения и голосовое.

Ниже свёрнуто то, что нужно редко: журнал для отладки, ручные заходы по шагам
и обслуживание.

## Работа

1. **Аккаунты** — «Добавить аккаунт»: спросит имя, прокси и способ входа.
   Способа три:
   - **по QR** — код появится прямо в панели, под журналом; сканируешь
     телефоном (Telegram → Настройки → Устройства → Подключить устройство).
     Код обновляется сам, пока его не отсканируют. Если на аккаунте стоит
     облачный пароль (2FA), вход по QR из панели не пройдёт — запусти руками:
     `venv-tg/bin/python login-qr.py --account a2 --password <пароль>`;
   - **готовой сессией** — выбираешь файл: TDATA (`.zip`) или `.session`
     (можно `.zip`, где вместе лежат `.session` и `.json`). QR не нужен;
   - **по номеру телефона** — Telegram присылает код, панель спрашивает его
     сама, отдельным окном, и так же спросит облачный пароль, если он стоит.
     Годится, когда сканировать QR нечем. Тем же способом можно войти в уже
     заведённый аккаунт — кнопка «Код» в его строке.

   Аккаунтов может быть сколько угодно; точкой в списке отмечаешь, от кого
   работать сейчас. Рядом с названием видно состояние: зелёное «вошёл» и имя
   с телефоном, как их отдал Telegram, либо красное «не вошёл» с подсказкой,
   что делать. Данные подтягиваются при каждом подключении, так что зелёная
   отметка означает именно живую сессию, а не запись в реестре. Кнопки строки: «Прокси» — сменить адрес, «Проверить IP» —
   убедиться, что прокси живой и пропускает Telegram, «Сессия» — залить
   TDATA/`.session` в этот аккаунт, «Имя» — переименовать, «Отключить» —
   удалить сессию с компьютера. У аккаунтов, заведённых до перехода на
   Telethon, есть ещё «На Telethon»: она берёт ключ из уже открытой браузерной
   сессии, сканировать QR заново не нужно.
2. **База номеров** — перетащи файл (Excel или CSV) в панель или нажми и выбери.
   Колонку с номерами панель находит сама; если номеров в файле нет вовсе,
   она поищет колонку с `@username` — так принимается готовый список людей.
   Таблица с номерами базу заменяет (загрузили новую — работаем по ней),
   а список `@username` её дополняет: номера при этом никуда не деваются,
   и люди, собранные из чатов, тоже остаются; тут же видно, сколько номеров вышло
   и первые строки. Если файл уже лежит на этом компьютере, можно вместо
   перетаскивания указать путь — в свёрнутом блоке под зоной загрузки.
3. **Проверить базу** — узнаёт, у кого из номеров есть Telegram. Людей, взятых
   из чата, этот шаг не касается — они в Telegram уже по факту.
   Вместо базы (или вместе с ней) получателей можно собрать прямо из чатов —
   см. «Получатели из чатов».
4. **Написать найденным** — кладёт текст из `message.txt` черновиком в чат
   с человеком. По умолчанию **останавливается на черновике**: заходишь
   в Telegram, читаешь, отправляешь сам. Черновик синхронный — он виден и на
   телефоне. С галочкой «отправлять сразу» панель отправляет сама: сообщение
   уходит человеку, отозвать нельзя.
5. **Автопрогон** — то же самое, но без нажатий: панель сама гоняет пачки
   всеми отмеченными аккаунтами, пока база не кончится. Подробности ниже.
6. **Сводка** — кто из базы ответил и какие черновики ждут отправки.

Текст сообщения правится **прямо в панели**, в шаге 4: под текстом сразу видно,
как его прочитает человек. Кнопка «Сохранить текст» пишет его в `message.txt` —
файл никуда не делся, править можно и там. Подстановки: `{name}` — имя из
Telegram, `{date}` — дата звонка.

**Паузы по умолчанию** выставлены по осторожному краю, и уменьшать их не стоит:

| | по умолчанию |
|---|---|
| между «завёл контакт» и «написал» | 60–120 с |
| между людьми | 180–350 с |
| сообщений за заход на аккаунт | 2 |
| отдых после захода | 40–60 мин |

Обе паузы — вилки, а не ровные числа: одинаковый интервал виден по секундомеру
не хуже, чем полное его отсутствие. Контакт заводится строго по одному и
удаляется сразу после отправки; забытые с прошлых сбоев подчищаются в начале
каждого захода — адресная книга, набитая чужими номерами, это примета, по
которой аккаунт и ловят.

**Голосовое.** В том же шаге 4 можно вместо текста разослать голосовую заметку.
Нажми «Загрузить голосовое» и выбери любой аудиофайл — панель сама переведёт
его в формат голосовых Telegram (нужен `ffmpeg`; уже готовый `.ogg` берётся
и без него). Галочка «отправить голосовым вместо текста» включает этот режим.
**Важно:** голосовое нельзя оставить черновиком — оно уходит человеку сразу,
как отправка с галочкой. Поэтому режим всегда спрашивает подтверждение; начинай
с маленького «за раз». Одному человеку шлём один раз — тот, кому уже написали
или отправили голосовое, второй раз не получит.

## Получатели из чатов

Не у всех есть телефоны. Второй способ набрать людей — взять их прямо из групп
и каналов: панель проходит по списку участников и кладёт их в **ту же очередь**,
что и проверенные номера. Дальше с ними работает обычная рассылка: те же паузы,
те же дневные пределы, те же брони и то же правило «одному человеку пишем
один раз».

**Папкой — основной способ.** Вступать в чаты всё равно приходится руками,
а вот перечислять их панели по одному незачем. Сложи чаты в Telegram в папку
(Настройки → Папки; папки видно слева от списка чатов), впиши её название
в панели — по умолчанию `chats` — и нажми «Собрать из папки». Панель пройдёт
по ней сама, чат за чатом, пока они не кончатся или пока не упрётся в предел
за заход.

Где остановилась — **помнит**: пройденные до конца чаты записаны в `chats.json`,
и следующий заход начинается с неразобранных. Поэтому «упёрлись в предел»,
«Telegram попросил паузу» и «нажали Остановить» — это не потеря работы,
а просто пауза: запусти разбор ещё раз. Галочка «пройти заново» нужна только
когда в старые чаты пришли новые люди и их надо добрать.

**Предел за заход** — общий на весь обход папки, а не на чат. Набрали столько
людей — панель останавливается. `0` снимает предел.

**Одним чатом.** Если нужен ровно один чат, есть поле для ссылки: годится
`https://t.me/имя_чата`, `@имя_чата`, числовой id или приглашение `t.me/+…`.

Собирает **первый отмеченный аккаунт** — он и должен состоять в этих чатах.

Что важно знать:

* **Проверять их не нужно.** Человек в чате — уже человек в Telegram, шаг
  «проверить базу» для него просто нечего делать. В очередь он попадает сразу
  как найденный.
* **Ключ вместо номера.** В `results.csv` у таких людей в колонке `phone`
  стоит `@username`, а у кого ника нет — `id:<номер>`.
* **Ботов, удалённых и себя** панель отбрасывает сама.
* **Закрытые списки пропускаются.** Если в чате список участников скрыт
  настройками или аккаунт в него не входит, панель скажет об этом в журнале
  и пойдёт к следующему чату — весь обход из-за одного чата не встанет.
* **Сколько отдаст Telegram.** У больших публичных чатов постранично видно
  первые ~10 000 участников — это предел Telegram, а не панели. В части групп
  список участников закрыт настройками, и тогда не видно никого.
* **Вступление.** Закрытый чат по ссылке-приглашению читается только изнутри.
  Галочка «вступить, если аккаунт не состоит» разрешает панели войти в чат;
  без неё она честно скажет, что участников не видно. Это только для разбора
  по ссылке: в папку чаты складывает человек, значит, он в них уже вошёл.
* Собранное лежит в `members.csv`, кнопка «Скачать список участников» отдаёт
  его файлом для Excel.

### Собирает один, пишут все

Разбор чатов занимает **один** аккаунт: пока он ходит по папке, остальные
отмеченные продолжают своё — проверяют номера и пишут. Задачи идут параллельно,
как и всегда: один аккаунт — одна задача за раз.

А вот **рассылка по собранным делится между всеми** — ради этого они и лежат
в общей очереди. Тут есть одна честная оговорка, и её стоит знать заранее:

* **у кого есть `@username`** — того напишет любой аккаунт панели. Такие люди
  делятся бронями между всеми отмеченными, ровно как номера;
* **у кого ника нет** (`id:<номер>`) — того видит только аккаунт, который его
  нашёл. Так устроен Telegram: доступ к человеку выдаётся каждому аккаунту
  свой и живёт в его сессии, передать его нельзя. Панель это знает: чужим
  аккаунтам такие люди не достаются вовсе, автопрогон не гоняет по ним пустые
  заходы, и никто их не «сжигает» неудачными попытками.

В обычном чате ник есть примерно у двух третей — то есть большая часть базы
раскладывается по всем аккаунтам сразу. Если этого мало и хочется, чтобы
делилось **всё**, поставь галочку «брать только тех, у кого есть @username»:
база выйдет меньше, зато целиком общая. Панель в любом случае показывает
расклад: «столько-то напишет любой аккаунт, столько-то — только сборщик».

Отсюда же практический порядок работы: пусть один аккаунт разбирает чаты
(это чтение, лимиты у него тратятся иначе, чем у рассылки), а писать запускай
всеми — включая сборщика, ему достанутся «его» люди без ников.

**Готовый список тоже подойдёт.** Если люди уже собраны где-то ещё, перетащи
в панель обычный CSV с колонкой `username` (и, если есть, `name`) — панель
поймёт, что номеров в файле нет, и заведёт их так же, как разбор чата.
Такой список ничего не стирает: он добавляется к тому, что уже есть.

**Про текст.** Очередь у номеров и у людей из чатов общая, а значит, и текст
сообщения общий. У человека из чата **нет даты звонка**, поэтому подстановка
`{date}` оставит у него пустое место («звонили .»). Панель предупредит об этом
прямо под текстом и покажет, как письмо прочитают оба — человек из базы
номеров и человек из чата.

## Потренироваться, никого не задев

Прежде чем пускать панель на живую базу, есть чем потренироваться:

```
venv-tg/bin/python make-test-base.py
```

Скрипт кладёт рядом `тест-база.xlsx` — её можно перетащить в панель, как
обычную базу. Номера в ней **свои**: те, что уже отмечены в `results.csv` как
«есть в Telegram» (после чистки берёт их из последнего бэкапа). Случайных
номеров скрипт не выдумывает намеренно: черновик лёг бы живому человеку в чат,
а с галочкой «отправлять сразу» ему бы и ушёл. Свои номера можно перечислить
руками: `--numbers +79045439815,+79120479425`.

Кроме рабочих строк в файл кладутся заведомо негодные — городской номер,
маскированный, обрезанный, текст вместо номера. Панель обязана их отбросить
при разборе: в журнале это видно строкой «отброшено».

**Кусок настоящей базы.** Чтобы попробовать на живых номерах, но небольшой
пачкой, тот же скрипт умеет отрезать от большой базы:

```
venv-tg/bin/python make-test-base.py --from ~/Desktop/база/numbers.csv --take 50
```

Берёт самые свежие звонки и **выбрасывает тех, кого уже трогали** — смотрит
`results.csv` и `drafts.csv` и рядом с исходником, и в самой панели. Это защита
от второго сообщения одному человеку: учёт панели чистка обнуляет, а люди
помнят. Отключается флагом `--all`, но без нужды его лучше не трогать.
Исходником годится и `.xlsx`, и `.csv` — колонки скрипт находит сам.

Одному человеку панель пишет один раз, поэтому со второго захода она скажет
«черновиков к раскладке: 0». Чтобы потренироваться ещё раз:

```
venv-tg/bin/python forget-numbers.py
```

Он убирает отметки «писали» — номера возвращаются в очередь на черновики.
С `--checks` забывает и результат проверки. На живой базе так делать не нужно:
человек получит второе сообщение.

## Прогрев аккаунтов

Свежекупленный аккаунт, который сразу пишет полусотне незнакомых людей, — это
мёртвый аккаунт: Telegram выдаёт PEER_FLOOD в первые же часы. Живые аккаунты так
себя не ведут. Поэтому панель ведёт каждый новый аккаунт по расписанию:

| возраст аккаунта | сколько человек в сутки |
|---|---|
| первые сутки | **0 — отлёжка**, вообще ничего не делаем |
| 1–2 день | 2 |
| 3–4 день | 5 |
| 5–6 день | 8 |
| 7–9 день | 12 |
| с 10-го | 15 |

Возраст считается от подключения сессии (поле `warmFrom` в `accounts.json`).
Аккаунт, который успел поработать **до** появления прогрева, в отлёжку не
загоняется — ему сразу засчитывается зрелый возраст.

Что это меняет на практике:

- на отлёжке аккаунт не берут ни в проверку, ни в рассылку — даже вручную
  (панель откажет и скажет, сколько осталось);
- размер захода урезается под дневной предел: аккаунту на 2-м дне уйдёт
  `--limit 2`, а не 25;
- выбрал предел — уходит до завтра, остальные продолжают;
- в строке аккаунта видно: `🌱 день 3 · разгон: 5 в сутки · сегодня осталось 4`.

Отключается галочкой «Беречь новые аккаунты (прогрев)» в блоке запуска. Из двух
пределов — твоего ручного и того, что даёт прогрев — всегда берётся меньший.

**Пачкой.** Кнопка «Залить пачку сессий» принимает сразу много файлов
(`.zip` TDATA или `.session`): панель заводит по аккаунту на файл, имя берёт из
имени файла, прокси спрашивает один раз на всех. У каждого нового начинается
своя отлёжка.

## Аккаунт в Telegram Desktop

Кнопка «Открыть в Desktop» в строке аккаунта. Работает, потому что `tdata` —
это родной формат Telegram Desktop: аккаунт открывается там по-настоящему.

**Нужен именно Telegram Desktop** (`com.tdesktop.Telegram`), а не нативный
клиент Telegram для macOS (`ru.keepcoder.Telegram`) — тот про `tdata` ничего не
знает. Панель проверяет, что стоит, и подскажет:

```
brew install --cask telegram-desktop
```

**Открывается в два шага, и это не формальность.** Ключ у десктопа и у панели
один и тот же. Если десктоп выйдет в сеть мимо прокси, Telegram увидит одну
авторизацию с двух разных IP — это первая причина, по которой отзывают сессии.
Поэтому:

1. **Подготовить** — десктоп стартует на пустой папке, аккаунта в ней нет,
   светить нечего. Прописываешь прокси (Настройки → Продвинутые → Тип
   соединения → Свой прокси) и закрываешь окно.
2. **Открыть** — только теперь панель кладёт `tdata` рядом с уже настроенным
   прокси и запускает снова. Аккаунт выходит в сеть сразу через прокси.

У каждого аккаунта своя папка `desktop/<id>` (ключ `-workdir`), поэтому
несколько десктопов спокойно живут рядом. Полная чистка папку `desktop/`
удаляет — там лежат ключи.

**Не выходи из аккаунта в десктопе** — ключ общий, панель потеряет сессию тоже.

## Профиль аккаунта из панели

Три отдельные кнопки в строке аккаунта — тем же ключом, которым работает панель:

- **Имя в TG** — имя и фамилия, как их увидят люди в переписке;
- **@ник** — username (Telegram откажет, если занят);
- **Аватар** — картинка `.jpg`/`.png`.

Рядом «Ярлык» — это название только внутри панели, в Telegram оно не уходит.

Открыть аккаунт в браузере нельзя, и это не недоделка: сессия Telethon — ключ
MTProto, браузеру он не подходит. Чтобы зайти в Telegram Web, аккаунту пришлось
бы логиниться заново по QR, то есть заводить вторую сессию на тот же номер —
лишний вход, который Telegram считает подозрительным. Поэтому профиль правится
напрямую.

Руками то же самое:

```
venv-tg/bin/python profile.py --account a1 --name Андрей --about "Подбор техники"
venv-tg/bin/python profile.py --account a1 --photo ~/avatar.jpg
```

## Автопрогон

Шаги 3 и 4 — это одна пачка на одно нажатие. Автопрогон (шаг 5) делает то же
самое сам и сразу всеми отмеченными аккаунтами: каждый берёт свою пачку,
отдыхает паузу и берёт следующую. Настройки не дублируются — размер пачки,
паузы, текст и галочка «отправлять сразу» берутся из шагов 3 и 4.

Что можно задать в самом шаге 5:

- **что делать** — «проверять и писать» (по умолчанию), «только проверять»
  или «только писать уже найденным»;
- **пауза между пачками** — сколько аккаунт отдыхает между своими пачками;
- **не больше N в сутки на аккаунт** — дневной предел отправок. Выбрав его,
  аккаунт молча уходит до завтра, остальные продолжают. `0` — без предела.

Пока прогон идёт, вместо галочек видно, чем каждый аккаунт занят, сколько
пачек уже сделал и через сколько возьмётся за следующую.

**Кто чем занимается.** Аккаунт берёт рассылку, если есть кому писать, иначе
идёт проверять базу. Так первые найденные получают сообщение, не дожидаясь,
пока прогон дойдёт до конца базы.

**Пересечься аккаунты не могут** — номера делятся теми же бронями, что и при
ручном запуске: один номер в один момент только у одного аккаунта, и одному
человеку пишет только один.

**Что останавливает прогон:**

- база пройдена и всем найденным написано — прогон закончился сам;
- Telegram придержал аккаунт (PEER_FLOOD, кончилась квота на контакты) — этот
  аккаунт уходит отдыхать ровно на столько, сколько просит Telegram (после
  PEER_FLOOD — часами), остальные работают дальше. В журнале видно, до какого
  времени он отдыхает;
- задача трижды подряд не запустилась или упала (мёртвая сессия, нет сети,
  прокси) — аккаунт выбывает из прогона, прогон продолжается без него;
- кнопка «Остановить» — гасит и автопрогон, и все идущие задачи.

Номер, который трижды не вышло обработать, откладывается — иначе прогон
крутился бы на одном и том же месте.

**Осторожно.** С галочкой «отправлять сразу» автопрогон сам пишет живым людям
пачка за пачкой, и отозвать это нельзя. У аккаунта, который получил PEER_FLOOD,
работать без предела — верный способ его потерять. Ставь дневной предел,
начинай с маленьких пачек и больших пауз.

## Готовые сессии: TDATA и SESSION+JSON

Кроме входа по QR аккаунт можно подключить готовой сессией — так подключают
купленные аккаунты, телефон и код не нужны.

- **TDATA** — папка от Telegram Desktop. Заворачивают в `.zip` (папка `tdata`
  может лежать на любом уровне архива). Панель читает оттуда ключ.
- **SESSION** — файл `.session` (Telethon или Pyrogram), можно прямо
  или в `.zip`. Ключ и номер дата-центра лежат внутри самого файла, `.json`
  рядом больше не нужен: он требовался только Telegram Web.

Из любого источника получается своя сессия Telethon — `sessions/<id>.session`.
Дальше аккаунт работает только с ней; папки браузерных профилей (`tg-profile`,
`accounts/`) остаются нетронутыми и панели больше не нужны.

Панель сама определяет по файлу, TDATA это или `.session`, и подключает нужным
способом. **Живость проверяется по-настоящему**: подключение засчитывается,
только когда Telegram реально отдал данные аккаунта. Мёртвый или отозванный
ключ помечается как «нет входа», в работу не идёт.

> **Прокси и география.** Купленный аккаунт часто привязан к стране. Если он,
> скажем, американский, а зайти с российского IP без прокси — Telegram сбросит
> сессию, и аккаунт сгорит с первого захода. Такому аккаунту прокси задают
> **до** импорта (в диалоге добавления). Для TDATA нужен `opentele`
> (лаунчер ставит сам).

Из терминала то же самое:

```
venv-tg/bin/python import-account.py --account a2 --session файл.session
venv-tg/bin/python import-account.py --account a2 --tdata архив.zip
venv-tg/bin/python import-account.py --account a1 --from-profile
```

Последняя строка — разовый перенос аккаунта, который уже входил через браузер:
ключ берётся из его профиля Chromium, заново сканировать QR не нужно.

## Ссылки-зеркала: {LINK}

Одна и та же ссылка в тысяче писем — примета рассылки. Поэтому в тексте можно
писать `{LINK}`, и панель заменит его на живой субдомен `boldo-agency.ru`,
меняя адрес каждые 30–50 писем. Все субдомены ведут на один лендинг.

Настраивается в блоке «Что напишем» → «Ссылка-зеркало {LINK}». Два режима:

* **wildcard** (проще и надёжнее) — на проекте Vercel один раз заведён
  `*.boldo-agency.ru`. Тогда любой субдомен работает сразу, без обращений
  к API, без ожидания сертификата и без чистки. Панель просто придумывает имена.
* **api** — как в исходном ТЗ: каждый субдомен регистрируется отдельным
  запросом к Vercel (нужны токен и Project ID). Гибче, но медленнее: Vercel
  проверяет DNS и выпускает сертификат не мгновенно, есть предел доменов
  на проект, и старые панель удаляет сама раз в неделю.

Лендинг и готовый `vercel.json` лежат в `deploy/vercel-mirror/` — как их
развернуть, написано там же. Токен Vercel хранится на сервере, в браузер
панель его не отдаёт и на другой компьютер при обновлении кода не увозит.

**Важно про адрес API.** Правильный эндпоинт Vercel — `api.vercel.com`,
а не `vercel.com` (в первоначальном ТЗ был указан неверный).

## Варианты в тексте (spintax)

Одинаковые письма, разосланные пачкой, Telegram узнаёт по отпечатку. Поэтому
пиши одно сообщение, а где хочешь сказать по-разному — заключай варианты
в фигурные скобки через чёрточку:

    {Здравствуйте|Добрый день}{|{name}}! {Подбираю|Помогу подобрать} квартиру.

На каждого человека панель выбирает свой вариант — письма не повторяются слово
в слово. Пустой вариант — просто пропуск: `Привет{|{name}}` даёт «Привет» или
«Привет, Имя». Вложенность работает. Панель под полем показывает, сколько
непохожих писем получается, и три примера.

Подстановки прежние и работают внутри вариантов: `{name}` — «, Имя» (с запятой),
`{date}` — дата звонка, `{username}` — ник, `{LINK}` — ссылка-зеркало.


## Две ступени: вопрос, потом ссылка

Ссылку в первом же сообщении незнакомому человеку Telegram не любит, да и
человек тоже. Поэтому рассылку можно разложить на два шага:

1. **первое письмо** — вопрос без ссылки (обычный текст из шага «Что напишем»);
2. **второе письмо** — со ссылкой, и уходит оно **только тем, кто ответил**.
   Кто промолчал, второго не получит вовсе.

Включается галочкой «Включить второй шаг» там же, где пишется текст. Работает
только в режиме отправки: черновиком ссылку не оставишь, человек уже ответил
и ждёт.

Как панель понимает, что ответили: смотрит чат с человеком — если последнее
слово в диалоге не наше, значит он ответил. Вечно висящего обработчика событий
для этого не нужно, и это сознательно: держать живое соединение на каждый
аккаунт — постоянная активность с одного адреса, ровно то, чего мы избегаем,
работая в один поток. Панель просто заглядывает в диалоги раз в полчаса, тем же
способом, что и «кто ответил» в сводке.

Кому второе письмо уже ушло, помнит `followup.csv` — дважды человек его
не получит.

## Прогрев поведением

Прогрев по расписанию (сколько сообщений в сутки можно) отвечает на вопрос
«сколько», но не отвечает на вопрос «как выглядит аккаунт». А выглядит он
пусто: ни на что не подписан, ничего не читает, ни с кем не переписывался —
и сразу пишет незнакомым. Это видно со стороны Telegram.

Блок **«Прогрев поведением»** водит аккаунты по обычным человеческим делам,
пока они молодые. Одно действие за раз, пауза 2–4 минуты, после двух-трёх
действий сон на 2–4 часа. Первые сутки аккаунт не трогается вовсе.

Что аккаунт делает:

* подписывается на открытые каналы из списка;
* запускает ботов, которые потом **сами шлют уведомления** — напоминалки,
  игровые события, ответы нейросетей. Входящие сообщения аккаунт себе не
  нарисует, а для Telegram это признак живого: с человеком разговаривают,
  а не только он;
* заходит в них, отмечает прочитанным, держится 5–15 секунд и ставит реакцию —
  именно в таком порядке: реакция сразу после входа выглядит как робот;
* голосует в опросах, если попадутся;
* вступает в открытые группы (с четвёртого дня);
* пишет другим **своим же** аккаунтам панели и отвечает им;
* раз в сутки спрашивает у `@SpamBot`, нет ли на нём ограничений, — ответ видно
  в строке аккаунта.

**Сколько чего в сутки** зависит от возраста аккаунта:

| | дни 1–3 | дни 4–6 | с 7-го дня |
|---|---|---|---|
| подписки на каналы | 1–2 | 2–3 | 4–5 |
| вступления в группы | 0 | 1–2 | 3 |
| реакции | 2–3 | 3–5 | 5–7 |
| сообщения своим | 0 | 1–2 | 1–2 |
| запуск ботов | 0–1 | 1–2 | 1–2 |

Предел на сегодня выбирается из вилки один раз в сутки и не скачет между
запусками — иначе он не был бы пределом.

**Куда водить** — файл `warm-list.json` рядом с панелью: каналы, группы, боты,
фразы для переписки, набор реакций. Правь смело, панель перечитывает его на
каждом действии. Канала, которого не окажется, панель коснётся один раз,
пометит и больше к нему не вернётся.

В списке ботов намеренно нет некоторых из ходовых: `@GmailBot` просит доступ
к вашей почте, `@Stickers` ничего не шлёт сам, `@AnonRuBot` и
`@VoicesOfStrangers_bot` сводят с незнакомцами, а инлайновые `@gif`, `@pic`,
`@music` работают внутри чужого чата, и «запустить» их нечем. Нужны — впиши
руками, файл твой.

**Про один адрес на всех.** Два аккаунта, активничающие с одного IP в одну
минуту, — это то самое, за что выдают ограничения. Панель следит сама: если
у аккаунтов один прокси на всех (или прокси нет вовсе — тогда адрес один,
серверный), прогрев водит их строго по одному. А если задана ссылка смены IP,
то между аккаунтами ещё и меняет адрес — одна сессия, один адрес.

Прогрев не лезет туда, где идёт настоящая работа: аккаунт, занятый рассылкой
или проверкой базы, в этот момент не трогается.

## Один мобильный прокси на всех: работа по очереди

Обычно у каждого аккаунта свой прокси, и тогда они спокойно работают
параллельно. Но мобильный прокси с ротацией устроен иначе: адрес один на всех,
зато его можно менять по ссылке из личного кабинета. Работать через такой
параллельно бессмысленно — все аккаунты в один момент сидят на одном адресе,
и смена его ничего не даёт.

Для этого есть **режим по очереди**. В каждый момент работает ровно один
аккаунт; закончил — панель дёргает ссылку смены IP, ждёт, пока оператор поднимет
соединение заново, и запускает следующего. База при этом делится ровно так же,
бронями: люди не задваиваются, просто аккаунты идут друг за другом, а не разом.

Настраивается в блоке «Запуск», в разделе «Мобильный прокси со сменой IP»:

* **ссылка смены IP** — та, что даёт провайдер прокси (у mobileproxy.space это
  что-то вроде `api.html?command=reboot&proxy_id=…`). Кнопка «Проверить» дёргает
  её прямо сейчас и показывает ответ — лучше убедиться до запуска, чем узнать
  о неверной ссылке в середине прогона;
* **сколько ждать после смены** — оператору нужно несколько секунд, чтобы
  физически переподключиться. Начнёшь раньше — пойдёшь со старого адреса.
  По умолчанию 10 секунд, меньше пяти обычно мало.

Вписанная ссылка сама включает режим «по очереди» — иначе смысла в ней нет.
Режим можно включить и без ротации, просто галочкой, если по какой-то причине
не хочется, чтобы аккаунты работали одновременно.

**Очередь честная**: следующим идёт тот, кто дольше всех не работал. Иначе
первые в списке забирали бы заход за заходом, а последние ждали бы, пока
у первых кончится дневной предел.

**Если прокси не отвечает** — панель пробует трижды, с паузой в минуту, и потом
останавливает прогон. Продолжать нельзя: это значило бы слать всё с одного
адреса, ради смены которого режим и включали.

Не забудь поставить этот прокси **всем** аккаунтам — панель меняет адрес,
но не решает за тебя, кто через него ходит. Для этого в шаге 1 есть кнопка
**«Прокси всем»**: вписал один раз — встал на все аккаунты сразу.

## Под каким устройством заходят аккаунты

Десять аккаунтов, заходящих с одинаковым «Desktop / Windows 10», — это десять
одинаковых отпечатков, и по ним их видно как одну связку. Поэтому каждому
аккаунту достаётся **своё** устройство: телефон, версия Android и версия
клиента, которые бывают вместе в жизни. Видно в строке аккаунта.

Правила простые:

* устройство выбирается **один раз** и навсегда записывается в `accounts.json`.
  Менять его у живой сессии нельзя: для Telegram это выглядит так, будто
  человек посреди дня пересел на другой телефон, не выходя из аккаунта;
* два аккаунта не получают одинаковый телефон — выбор идёт из ещё не занятых;
* если сессию купили вместе с `.json` от авторегера, панель берёт **родные**
  параметры оттуда (`device`, `sdk`, `app_version` и как их ещё называют)
  и закрепляет за аккаунтом. Заходить купленной сессией под своим устройством
  нельзя — Telegram увидит смену;
* аккаунты, которые уже вошли до этого изменения, остаются со старым
  «Desktop / Windows 10». Менять им устройство задним числом опаснее, чем
  оставить как есть.

## Карантин: когда Telegram уже сделал замечание

Перед каждым заходом рассылки аккаунт спрашивает у `@SpamBot`, нет ли на нём
ограничений. Это единственный способ узнать: на отправку Telegram ошибкой не
отвечает, он просто перестаёт доносить сообщения — аккаунт пишет в пустоту,
а панель считает это успехом.

Если бот ответил про ограничение, аккаунт получает статус **«карантин»**:

* рассылка и второе письмо с него не идут — ни руками, ни автопрогоном;
* автопрогон не берёт его в набор и говорит об этом в журнале;
* **база остаётся на месте**: ничего не теряется, люди вернутся в очередь
  к другим аккаунтам;
* проверка базы, разбор чатов и прогрев поведением продолжают работать —
  это не рассылка, и через них аккаунт как раз отлежится;
* карантин держится сутки: ограничения обычно снимаются по времени, и вечно
  вычёркивать аккаунт из-за вчерашнего вердикта неправильно.

Неоднозначный ответ бота панель считает плохим: ошибиться в сторону
«поработай завтра» дешевле, чем погнать в рассылку аккаунт, которому Telegram
уже сделал замечание.

## Прокси

Каждому аккаунту можно задать свой прокси: первый ходит напрямую, второй —
через купленный адрес. Форматы, которые панель понимает:

    1.2.3.4:8000
    1.2.3.4:8000:логин:пароль
    http://логин:пароль@1.2.3.4:8000
    socks5://1.2.3.4:1080

Пустая строка — ходить напрямую, со своего IP.

**SOCKS5 с логином и паролем работает** — Telethon умеет его сам, без всяких
мостов. Просто впиши прокси как есть, включая `socks5://user:pass@host:port`.
(Локальный мост `socks-bridge.mjs` остался для старых браузерных скриптов:
Chromium такое не умеет.)

**Прокси должен пропускать сам Telegram.** Кнопка «Проверить IP» смотрит обе
вещи сразу: меняется ли адрес и доходит ли соединение до дата-центра Telegram.
Если адрес меняется, а дата-центр недоступен — прокси не годится, работать
через него панель не сможет.

**Прокси задаётся до входа по QR** — панель спрашивает его сразу при создании
аккаунта. Так сессия с самого начала привязана к нужному адресу: если войти
напрямую, а потом переключить на прокси, Telegram увидит смену IP у живой
сессии, и это ровно то, чего мы избегаем.

Кнопка **«Проверить IP»** показывает твой адрес, адрес аккаунта и доступность
дата-центра. Если адреса совпали — трафик идёт мимо прокси. Проверять стоит
до входа: на мёртвом прокси QR всё равно не отсканируется.

## Несколько аккаунтов

Аккаунты работают **параллельно**: у каждого свой профиль, свой процесс и,
если задан, свой прокси. Ограничение одно — один аккаунт делает одну задачу
за раз, потому что профиль Telegram занимает ровно один процесс. Пока первый
идёт по базе, второй может идти по ней же.

База при этом **общая**, и делится она бронями. Перед работой аккаунт
резервирует свою пачку номеров, и пока бронь висит, другим они не достаются —
двое не пройдут по одному номеру и не напишут человеку дважды. Сколько номеров
у кого в работе, видно в панели («держит N»).

Бронь снимается, как только номер отработан и записан в результаты. Если
прогон остановили или процесс упал — брони снимаются на выходе, а зависшие
протухают через час. Запертых навсегда номеров не бывает.

Смысл всего этого в лимитах: квота на добавление контактов считается на
аккаунт, поэтому два аккаунта дают вдвое больше номеров в день.

Гонять их всех одновременно и без нажатий умеет автопрогон — см. раздел выше.

У каждого аккаунта своя папка сессии: первый живёт в `tg-profile`,
остальные — в `accounts/<id>`. Реестр — `accounts.json`.

## Важно

- **У Telegram есть лимит на добавление контактов.** Примерно после тридцати
  за день квота кончается, дальше проходит по одному раз в несколько минут.
  Это ограничение Telegram, ускорить его нельзя. Работать порциями.
  Когда квота кончилась, Telegram отвечает «повторите позже»: панель пишет
  об этом и сама останавливает прогон после трёх таких подряд.
- **PEER_FLOOD** — отдельная беда: так Telegram помечает аккаунт, который
  пишет слишком многим. Панель останавливается сразу, без попыток продолжить:
  дальше можно и вовсе потерять аккаунт. Дай ему отлежаться сутки.
- **Задержки между номерами имеют смысл.** По родному протоколу всё делается
  за секунды, и соблазн гнать без пауз велик — но лимиты считает Telegram,
  а не панель. Пауза в поле «раз в … секунд» — единственная защита.
- **Отправка необратима.** Без галочки «отправлять сразу» панель доводит
  только до черновика — это режим по умолчанию, и он безопасный.

## Чистка: выйти из всех аккаунтов

Кнопка «Выйти из всех аккаунтов и очистить» (в свёрнутом блоке «Обслуживание»)
возвращает панель в состояние «как новая»:

1. каждый аккаунт **выходит из Telegram по-настоящему** — сессия отзывается,
   в «Устройствах» на телефоне её больше нет;
2. аккаунты пропадают из списка панели;
3. база, результаты, история сообщений, загруженные файлы, реестр аккаунтов
   и файлы сессий уезжают в папку `_backup_<дата>` рядом с панелью.

Выход — это работа по сети, поэтому идёт он не мгновенно: ход виден в журнале,
кнопка ждёт сама.

**Что остаётся:** вход в панель (`auth.json`), текст сообщения (`message.txt`)
и **сводка за всё время**. Числа (проверено / найдено / написано / отправлено)
перед чисткой складываются в `stats-cache.json` и показываются под кружками —
поэтому итог не сбрасывается ни на единицу, сколько бы раз ни чистили.
Там же видно, когда была последняя чистка и в какой папке лежат её данные.

**Аккаунт после этого не вернуть прежним способом.** Отозванная сессия мертва
у всех: залитый TDATA или `.session` больше не подойдёт, входить придётся
заново — по QR или телефону. Если у какого-то аккаунта выйти не удалось (нет
связи, мёртвый ключ), его файл сессии не удаляется, а уезжает в бэкап —
такой аккаунт можно вернуть, положив сессию обратно.

Обычное «Отключить» в строке аккаунта работает иначе: оно только удаляет
сессию с этого компьютера, в Telegram она остаётся висеть.

## Как разложен код

```
admin.mjs          точка входа: конфиг, HTTP-сервер, маршруты
server/            куски бэкенда по смыслу
  csv.mjs          чтение наших CSV
  stats.mjs        числа панели и накопительная сводка
  warmup.mjs       расписание прогрева аккаунтов
  desktop.mjs      Telegram Desktop: найти, распаковать tdata, запустить
web/               всё, что видит браузер
  index.html       только разметка
  app.css          оформление
  app.js           весь клиентский код
*.py               задачи: проверка, рассылка, разбор чатов, вход, профиль, сборка базы
```

Статика отдаётся из `web/` по закрытому списку файлов — путь из запроса
не подставляется, иначе из папки можно выйти и прочитать чужое.

**Загрузка базы по пути работает только на локальной панели.** Путь приходит
из браузера, и на сервере, доступном снаружи, это чтение произвольных файлов.
Наружу остаётся перетаскивание файла — оно безопасно.
