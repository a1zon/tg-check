# tg-check — техническая база

Веб-панель для управления пулом Telegram-аккаунтов: подключение сессий, прокси и смена IP, прогрев поведением, профиль и аватарки, открытие аккаунта в Telegram Desktop, разбор чатов, поиск горячих лидов, ИИ-модуль. Бэкенд на Node, вся работа с Telegram — Python-задачи на Telethon.

Секретов в этом документе нет — только где они лежат. Пароли, ключи и ссылки с `api_key` в чат не вставлять.

## 4. Аккаунты

- **Подключение:** кнопка «Сессия» → архив tdata или .session → `import-account.py` (opentele `UseCurrentSession` — ключ тот же, нового «устройства» не появляется). Ещё вход по QR и по коду.
- При каждом подключении `tglib.connect()` проверяет ключ: мёртвый → `authed=false`; живой → обновляет имя/@/телефон/`user_id` и раз в сутки аватарку.
- **Если после массовой загрузки аккаунт «не вошёл»** — обычно просто не прошло первое подключение через мобильный прокси. Повторить «Сессия» тем же архивом (или `sudo -u tgpanel venv-tg/bin/python import-account.py --account aN --tdata uploads/aN-...zip`).
- Экран «Аккаунты»: аватарка, крупно имя, мелко номер и @ник; строки «прогрев» и «сейчас» с причиной ожидания.
- Смена имени/аватарки: кнопки у аккаунта. Совет: не всем сразу с одного IP, разные фото на разных аккаунтах.

## 5. Прокси и IP

- У каждого аккаунта строка прокси: `http://host:port:user:pass`, `http://user:pass@host:port`, `socks5://…`. Сейчас все на одном мобильном HTTP-прокси `176.9.154.69:9248` (логин/пароль — в `accounts.json`).
- **Смена IP:** ссылка ротации провайдера (`warmup.rotate`). Когда прокси общий, работа идёт строго по одному аккаунту, перед каждым — смена IP и пауза `rotateWait` (10 с). Провайдер иногда отвечает 400 на слишком частую смену — панель повторяет.
- Проверка прокси: кнопка «IP» у аккаунта (`proxy-check.py`).
- `socks-bridge.mjs` — мост для Chromium (он не умеет SOCKS5 с паролем).

## 6. Telegram Desktop на Маке

- Нужен **Telegram Desktop** (`com.tdesktop.Telegram`, `brew install --cask telegram-desktop`), не нативный Telegram для macOS — тот не понимает tdata.
- Каждому аккаунту своя папка: `…/Telegram -workdir <папка>`, в `<папка>/tdata` кладутся файлы из архива (`key_datas`, `D877F783D5D3EF8C*`). Настройки (`settingss`) в архиве нет — **tdata докладывать поверх, а не заменять папку**, иначе теряется настройка прокси. В панели (`unpackTdata`) сейчас заменяет — это баг, если открывать через панель.
- **Desktop не отправляет логин/пароль HTTP-прокси** (прокси отвечает 407). Рабочая схема — локальный мост: Desktop → SOCKS5 `127.0.0.1:18080` без пароля → мост добавляет авторизацию → HTTP-прокси аккаунта. Мост — небольшой Python-скрипт на asyncio (SOCKS5/HTTP → CONNECT с `Proxy-Authorization`), запускался из временной папки; для постоянного использования его стоит положить в проект.
- Включить прокси в Desktop без ручного ввода: `Telegram -workdir <папка> -- "tg://socks?server=127.0.0.1&port=18080"` → «Connect Proxy».
- Через мобильный прокси Desktop грузится медленно; для просмотра можно без прокси (через системное соединение Мака), но это второй IP на ту же сессию — ненадолго.
- Ключ у Desktop и панели общий: **не выходить из аккаунта** в Desktop, закрывать окно (Cmd+Q) после просмотра.
- Проверка, что трафик идёт куда надо: `lsof -nP -a -p <pid> -i`.

## 7. Прогрев

Включается на вкладке «Прогрев». Автоматика (`warmTick` в `admin.mjs`) раз в 30 с выбирает аккаунт; за один запуск `warmup-activity.py` делает **одно** действие.

- **Отлёжка:** первые сутки после добавления аккаунт ничего не делает (`warmFrom`).
- **Сессии как у человека:** 2–3 действия подряд с паузой 2–4 мин, потом сон 2–4 ч.
- **Дневные потолки по возрасту** (`PLAN` в `warmup-activity.py`):
  - день 1–3: подписки 1–2, реакции 2–3, боты 0–1;
  - день 4–6: подписки 2–3, вступление в группы 1–2, реакции 3–5, переписка со своими 2–3, боты 1–2;
  - день 7+: подписки 4–5, группы 3, реакции 5–7, переписка 3–5, боты 1–2.
- **В начале каждого захода** аккаунт читает непрочитанное от своих аккаунтов (пауза 2–6 с на диалог).
- **Переписка со своими:** свои узнаются по `user_id` (не только по @нику), первое сообщение — через диалог, @ник или номер (номер на минуту в контакты, потом удаляется). Сначала отвечает тому, кто ждёт дольше; второе сообщение подряд без ответа не шлёт; фразы из `talk_open` (начать) и `talk_reply` (ответить), одну и ту же подряд не повторяет.
- **Фокус** (`dm_focus` в `warm-list.json`: `{"accounts":["a2"],"until":"ISO"}`) — остальные пишут и отвечают этому аккаунту первыми, сам он больше переписывается. Снимается сам по сроку.
- Раз в сутки аккаунт спрашивает **@SpamBot**.
- Пока аккаунт занят другой автоматической работой, прогрев его не берёт; освободившийся — догревается.

## 8. Ограничения Telegram — как панель их обрабатывает

- **SpamBot.** Ответ разбирается (`tglib.spam_verdict/spam_until`): временное ограничение с датой снятия (`spamKind=temp`, `spamUntil`) или бессрочное (`perm`), плюс причина (например, жалоба). Аккаунт встаёт на карантин ровно до даты снятия и возвращается сам; в ленте ⛔/✅. Отвечать тем, кто написал первым, под временным ограничением можно.
- **Квота на добавление контактов** (`ImportContacts` возвращает `retry_contacts`). Telegram не сообщает, когда она вернётся. Панель пишет `quotaUntil` в аккаунт (переживает перезапуск), через 12 ч пробует **один** номер; прошёл — снимает ожидание («✅ квота вернулась»). Опыт: после ~30–60 добавлений за день квота у этих аккаунтов закрылась на несколько суток; реальный потолок ≈ 20–30 в сутки, считать надо по скользящим 24 ч.
- **Флуд** (`FloodWait`, `PEER_FLOOD`) — пауза ровно на сколько просит Telegram; `PEER_FLOOD` — аккаунт выбывает до разбора.
- Адресная книга: контакты-метки (имя = 10 цифр) чистятся автоматически и кнопкой «Чистка контактов».
- Настоящее имя человека Telegram отдаёт, только если он **не** в контактах (иначе — имя контакта). `tglib.real_name()` спрашивает имя после удаления контакта; `human_name()` берёт первое слово из букв, отбрасывает эмодзи и «не имена».
- Папка в аккаунте по правилу (`tglib.ensure_outreach_folder`): «личные чаты не из контактов, кроме своих аккаунтов» — у обычной папки лимит 100 чатов, у правила — нет.

## 9. Автоматика панели — общее

- **Состояние переживает перезапуск:** `auto-run.json` пишется при запуске, удаляется при ручной остановке; после падения/выкладки панель сама продолжает («↺ перезапускалась — продолжено»).
- **Ручные действия ставят автоматику на паузу:** любая задача, запущенная руками (имя, аватар, вход, сессия, сводка…), останавливает выдачу новых задач автоматике и прогреву; через 2 мин после её конца всё продолжается. Кнопки у аккаунта блокируются только пока занят **именно он**. Исключение — «Desktop»: панель не знает, когда окно закрыли.
- **Рабочее время** для действий с людьми: 06:00–24:00 по Екатеринбургу (`WORK_TZ`), сервер живёт по UTC.
- **Лента «Что происходит»** (`server/events.mjs`) — разбор строк задач в события; время по Екатеринбургу; номера маскируются `+7950…2462`, аккаунты показываются по имени.
- Статус аккаунта считает сервер (`autoStatus`) — «работает / отдыхает до HH:MM, ещё N — причина / на сегодня всё / ночь / ограничен до …».

## 10. ИИ

- `llm.py` — один запрос к OpenAI-совместимому `/chat/completions` через `curl`, с прокси и повтором на 429/5xx. Настройки в `/opt/tg-panel/.env`: `LLM_BASE_URL` (OpenRouter), `LLM_API_KEY`, `LLM_MODEL`, `LLM_PROXY`, `LLM_BUDGET`. Самопроверка: `python3 llm.py`.
- Сейчас модель `deepseek/deepseek-v4-flash` (дёшево, ≈$0.05/$0.09 за 1M токенов). Бесплатные модели OpenRouter — около 50 запросов в сутки без пополнения; reasoning-модели льют рассуждения в ответ — вердикт вытаскивать регуляркой по последнему совпадению, при пустом ответе повторять.
- Прошлая версия `.env` — `.env.bak-2026-09-26`.

## 11. Сайт и связанные сервисы

- Лендинг `egor-kochnev.ru`: статический `index.html` (исходник в `deploy/egor-kochnev/`), nginx `egor-k`, `/var/www/egor`. Форма и события шлют POST в **Google Apps Script** (адрес в `CONFIG.sheetUrl` сайта и в `leads-sheet.txt`) → Google-таблица «Как я хочу M-очку», лист «Заявки». Метка источника — параметр `?src=`.
- Известная проблема формы: ответ Apps Script бывает 5–8 с и иногда 503; сайт ждёт ответа и не повторяет — стоит показывать «Спасибо» сразу и отправлять с повтором.
- **Сертификаты:** `egor-kochnev-pool` — один сертификат Let's Encrypt на `egor-kochnev.ru`, `www` и 95 имён-субдоменов из `mirror-names.txt` (HTTP-проверка, автопродление certbot). nginx `egor-k` смотрит на него. Wildcard через DNS не выпущен: домен на другом аккаунте reg.ru (`DOMAIN_NOT_FOUND`); хук `/etc/letsencrypt/regru-hook.py` и `regru.ini` лежат на случай, если дадут доступ.
- Субдомены в панели (`mirror.json`, режим `wildcard`) берутся только из `mirror-names.txt` — иначе у имени не будет сертификата.

## 12. Выкладка

```bash
cd ~/Projects/tg-check && bash deploy/push.sh root@46.16.15.238 --code-only
```

- Копирует код (без данных: сессий, реестра, csv, json, uploads, .env) и перезапускает `tg-panel`. Автоматика после перезапуска продолжает сама.
- Выкладывать в паузе между задачами: `pgrep -u tgpanel -fc "python.*\.py"` = 0 (ни одной Python-задачи не идёт).
- Сеть до сервера иногда рвётся (`Operation timed out`) — повторить.
- Сверка после выкладки: `md5sum` файлов на сервере против `md5 -q` локально.
- Браузер кеширует `app.js`/`app.css` — при правках интерфейса поднимать версию `?v=rNN` в `web/index.html`.

## 13. Проверка без прода

Python-задачи тестировались на «песочнице»: копия скриптов во временной папке, выдуманные CSV и `accounts.json`, а `tglib.connect` подменён заглушкой Telegram, которая хранит состояние в JSON (контакты, квота, SpamBot, папки, `GetUsersRequest`). Запуск: `runpy` скрипта с подменённым `tglib.connect`. Так проверяются крайние случаи (квота посреди работы, пропавший контакт, неактивный пользователь, повторный запуск) без трогания живых аккаунтов. Заглушка лежала во временной папке — при надобности пересобрать.

## 14. Грабли

- В интерфейсе окна `prompt/confirm/alert` браузера замораживают страницу (и инструменты автоматизации браузера).
- Выкладка/перезапуск во время задачи обрывают её; брони снимаются при выходе процесса.
- `accounts.json` пишут и панель, и Python-задачи — править руками только при остановленной панели.
- Один мобильный прокси на 19 аккаунтов: всё строго по очереди, каждый получает мало времени; стоит второй прокси.
- Время: сервер UTC, «сутки» лимитов считаются от UTC-полуночи (кроме проверок — скользящие 24 ч), рабочее время — по Екатеринбургу.
- В `.gitignore` добавлен `.env`. Данные и сессии в git не хранятся.
