# tg-check — полная техническая база продукта

Один документ обо всём устройстве. Подробности по отдельным темам — в соседних
файлах: [CODE.md](CODE.md) (как читать код), [HANDOVER.md](HANDOVER.md) (доступы
и передача), [TECH-BASE.md](TECH-BASE.md) (ограничения Telegram подробно).

Секретов здесь нет — только где они лежат. Пароли, ключи и ссылки с `api_key`
в чат не вставлять.

Актуально на 11.10.2026.

## 1. Что это

Веб-панель для рассылки в Telegram с пула аккаунтов. Ведёт аккаунты (подключение,
прокси, прогрев, профиль), рассылает в два независимых режима (по номерам из базы
и по людям из чатов), читает ответы и шлёт второе письмо, собирает горячих лидов,
обогащает по ЕГРЮЛ, и — отдельный слой — отдаёт аккаунт человеку на его компьютер.

Бэкенд на Node без фреймворков. Вся работа с Telegram — Python-задачи на Telethon.
Интерфейс — обычный HTML/JS без сборки.

одноразовый ключ `TG_PANEL_TOKEN`. Заголовок `Origin` дальше не шлёт (иначе профиль
отобьёт любой POST — так уже было).

## 3. Архитектура: три слоя

```
браузер → router.mjs → admin.mjs → python-задача → Telegram
          привратник    панель       задача        (через прокси)
```

**Панель ничего не делает с Telegram сама.** Она диспетчер: запускает по одной
Python-задаче на аккаунт, читает их вывод построчно и решает, когда звать аккаунт
снова. Последняя строка задачи — `⌁STATE {json}` (сколько сделано, осталось, не
придержал ли Telegram и на сколько) — это её отчёт планировщику. Остальные строки
идут человеку в журнал.

**Состояние живёт в файлах, а не в памяти.** Перезапуск панели не теряет ничего:
кто что написал, у кого кончилась квота, где остановился прогрев — всё в CSV и JSON
рядом с панелью. Поэтому выкладка безопасна, а `auto-run.json` поднимает прогон
после перезапуска сам.

**Один аккаунт — одна задача за раз.** Сессия Telethon — это SQLite-файл, два
процесса на одной сессии дают `database is locked`.

## 5. Аккаунты и сессии

- **Подключение:** кнопка «Сессия» → архив tdata или `.session` → `import-account.py`
  (opentele `UseCurrentSession` — тот же ключ, нового устройства не появляется).
  Ещё вход по QR (`login-qr.py`) и по коду (`login-code.py`).
- При каждом подключении `tglib.connect()` проверяет ключ: мёртвый → `authed=false`;
  живой → обновляет имя/@/телефон/`user_id` и раз в сутки аватарку.
- **«Не вошёл» после массовой загрузки** — обычно не прошло первое подключение через
  мобильный прокси. Повторить «Сессия» тем же архивом.
- **Роль:** `send` (в рассылке) или `warm` (только прогрев). Прогретый аккаунт
  переходит в рассылку сам (отметка `graduated`, один раз; ручной возврат в `warm`
  уважается). Это видно в журнале: «прогрев закончен — перешёл в рассылку».
- Смена имени/@ника/аватарки — `profile.py`. Совет: не всем сразу с одного IP,
  разные фото на разных аккаунтах.

## 6. Прокси и смена IP

- Строка прокси у аккаунта: `host:port:user:pass`, `user:pass@host:port`,
  `socks5://…`, со схемой или без (без схемы — HTTP). Разбор — `accounts.parseProxy`.
- Сейчас все на одном мобильном HTTP-прокси `176.9.154.69:9248` с ротацией по ссылке
  (`warmup.rotate`, **содержит ключ провайдера**).
- **Общий прокси ⇒ строго по очереди**, по одному аккаунту за раз, перед каждым —
  смена IP и пауза `rotateWait` (10 с). Это общий стоп-кран на оба режима рассылки.
- **Смену IP делаем только перед работой, которая светит аккаунт** (письма и проверка
  номеров), не перед чтением ответов. Промежуток между сменами — не чаще раза в 12
  минут. Каждая смена уводит модем из сети ≈ на минуту (в журнале «прокси лежит»);
  раньше смены впустую перед чтением ответов и были главной причиной «прокси падает».
- **Этот модем тянет короткие запросы (письма панели), но почти не тянет данные**:
  картинка 20 КБ с telegram.org едет ~38 с (299 байт/с), 1 МБ не вытягивает за минуту.
  Для просмотра аккаунта человеком он не годится — человеку нужен свой VPN/прокси.
- Латвийский VLESS-туннель на сервере (`tunnel-lv`, xray → SOCKS5 `127.0.0.1:10808`
  / HTTP `127.0.0.1:10809`) быстрый (3.6 МБ/с), но слушает только внутри сервера —
  снаружи к нему не подключиться.

## 7. Рассылка — два независимых режима

Набор получателей («по номерам» / «по чатам») — **свойство аккаунта**, не всей
панели. У каждой вкладки свой состав и свои настройки; режимы заканчиваются и
останавливаются независимо. Общий у них только **прокси** → общая очередь.

| | по номерам | по чатам |
|---|---|---|
| откуда люди | файл с номерами | разбор групп и каналов |
| нужна проверка | да, «есть ли Telegram» | нет, уже там |
| квота контактов | тратится | не тратится (пишем по @нику) |
| файлы | `numbers/results/drafts.csv` | те же в `chats/` |

- **Состав набирают галочками на вкладках рассылки** (не на «Аккаунтах» — там только
  показ). Занятый соседним режимом не выбирается. Состав меняется на ходу: кнопка
  становится «Добавить в работу: N» / «Снять с работы: N». Прогретый аккаунт на
  «только прогреве» можно взять прямо из вкладки — панель спросит и переведёт.
- **Проверка номеров и письмо — одна цепочка:** пока сегодня есть что написать, аккаунт
  берёт **один** номер → если есть Telegram и человек недавно заходил, сразу пишет →
  берёт следующий. Нашёл «нет»/«давно не заходил» — следующий, предел писем не тратит.
  Пачкой проверяет только когда писать нельзя (режим «только проверять», ночь,
  дневной предел выбран).
- **Проверок в сутки = письмам в сутки** (по графику разгона). Поле «потолок проверок»
  только опускает планку, выше дневного предела писем поднять не может.
- **Второй шаг (воронка)** — отдельная галочка у каждого режима: читает ответы раз в
  полчаса и досылает ответившим второе письмо. Текст второго письма общий на панель.
- **Рабочее время** для писем — 06:00–24:00 по Екатеринбургу (сервер живёт по UTC).
  Ночью спим **до 6:00 по Екб**, а не «до завтра» (иначе аккаунт просыпался в 5 утра
  по Екб = полночь UTC и снова засыпал на весь день — это чинилось).

## 8. Прогрев

Свежий аккаунт, сразу пошедший писать незнакомым, живёт недолго. Поэтому: сутки
отлёжки, потом постепенный набор. Две лестницы от даты добавления:

- **писем в сутки** — `server/warmup.mjs` (`WARM_PLAN`): 0 (отлёжка) → 2 → 5 → 9 → 15.
- **человеческих действий в сутки** — `warmup-activity.py` (подписки, реакции,
  группы, переписка со своими, боты).

Срок настраивается в панели (2–21 день, по умолчанию 7); обе лестницы
раскладываются на срок, отлёжка в первые сутки не сокращается. Переписываться
аккаунт может **только со своими** (другими аккаунтами этой панели) — для нормального
прогрева нужно хотя бы три. `TOP_UP` — редкий догрев, когда аккаунты уже отработали.

## 9. Ограничения Telegram

- **SpamBot:** временное ограничение с датой (`spamKind=temp`,`spamUntil`) или
  бессрочное (`perm`). Аккаунт встаёт на карантин до даты и возвращается сам.
  Отвечать тем, кто написал первым, под временным — можно.
- **Квота на контакты** (`ImportContacts` → `retry_contacts`): Telegram не говорит,
  когда вернётся. Панель пишет `quotaUntil`, через 12 ч пробует один номер. Реальный
  потолок этих аккаунтов ≈ 20–30 добавлений в сутки (скользящие 24 ч).
- **Флуд** (`FloodWait`,`PEER_FLOOD`): пауза ровно на запрошенное; `PEER_FLOOD` — 6 ч.
- Классификация ответа: «покупкой не занимаюсь» = **непонятно**, не «нет» (можем помочь
  с продажей). Логика в `followup.py` (`VERDICT_SYS`).

## 10. Доступ к аккаунту на компьютере человека

Это отдельный слой: отдать аккаунт человеку, чтобы он переписывался в настоящем
Telegram Desktop. Кнопка «На ПК» у аккаунта собирает **комплект** (zip) под его ОС.

**Три способа положить аккаунт в комплект** (`server/kit.mjs`, `kitEntries`):

1. **Отдельный вход** (по умолчанию, рекомендуется). Панель заводит аккаунту ВТОРУЮ
   авторизацию — ту же, что появляется при входе с нового компьютера — и кладёт её,
   а не свой ключ. `access.py` делает это обменом, которым Telegram логинит по QR:
   новый клиент просит токен, панель живой сессией подтверждает (`AcceptLoginToken`),
   новый клиент получает собственный ключ, из него `opentele` собирает tdata.
   **Проверено:** вход создаётся за 3 секунды, человек ничего не вводит.
   Такой доступ виден в списке устройств и **отзывается из панели одной кнопкой**;
   человек может спокойно выходить из аккаунта у себя — панели это не мешает.
2. **Без прокси** (галочка «у человека свой VPN»). Моста нет вовсе, аккаунт
   открывается сразу, адрес даёт компьютер человека. Нужен, т.к. мобильный прокси
   не тянет данные (см. §6).
3. **Ключ панели** (старый способ, галочку снять). Копия tdata самой панели: выйти
   нельзя (отзовётся у панели), убрать можно только стиранием файлов.

**Пульт** — один архив на несколько аккаунтов (`buildPult`, только Windows). Внутри
меню `Пульт.bat` и папка `akkaunty/`, где каждый аккаунт лежит обычным комплектом.
Меню запускает «Открыть аккаунт» нужной подпапки отдельным окном. **Ограничения «3
аккаунта на окно» нет**: у каждого своя папка данных = своё окно (проверено — три
окна Telegram живут одновременно). В окне скачивания — список «ещё аккаунты в пульт».

**Устройства и отзыв** (`/api/accounts/devices` → `access.py --list/--kill`): в окне
«На ПК» список «Кто имеет доступ к аккаунту» с кнопкой «выгнать» у каждого компьютера
и «выгнать всех, кроме панели». Панель всегда помечена, её не трогаем.

**Мост (для способов с прокси)** — Desktop не шлёт логин/пароль HTTP-прокси (отвечает
407). Поэтому: Desktop → SOCKS5 `127.0.0.1:18080` без пароля → мост добавляет
авторизацию → прокси аккаунта. Мост в комплекте (`kit/bridge.ps1` / `bridge.py`).
Telegram НЕ включает прокси по ссылке `tg://socks` (проверено на 7.2.9) — прокси
человек добавляет руками один раз: Settings → Advanced → Connection type → Use custom
proxy → Add proxy → SOCKS5, `127.0.0.1`, порт 18080, без логина/пароля.

**Очистка** (`kit/clean-win.ps1`, «Убрать аккаунт с компьютера.bat»): закрывает
Telegram и мост ЭТОЙ папки (чужой личный Telegram не трогает), удаляет tdata/workdir/
kit.json (с повторами; упрямые файлы — на удаление при перезагрузке средствами
Windows), **находит и удаляет все копии ЭТОГО аккаунта** рядом, в «Загрузках» и на
рабочем столе (по номеру в имени), включая скачанный архив. Выход в самом Telegram
для этого НЕЛЬЗЯ — отзовёт сессию и у панели.

**Ключевые находки из тестов на настоящей Windows 11 (в виртуалке UTM):**
- Путь с пробелом в имени ломал запуск — PowerShell не брал путь в кавычки, Telegram
  открывался со своей папкой без аккаунта. Это и было «сделал по гайду, не работает».
- Мост падал на каждом соединении Telegram: `return $buf` в PowerShell разворачивал
  массив в поток объектов, `[Net.IPAddress]` его не принимал. Лечится `return ,$buf`.
  Telegram всегда просит адрес цифрами, поэтому мост падал всегда; через домен
  (браузер/curl) работал и выглядел живым.
- Поиск Telegram через `where.exe` ронял скрипт (пишет в stderr + выходит с ошибкой,
  при `ErrorActionPreference=Stop` это обрыв). Добавлен поиск по ярлыку меню «Пуск».
- Чёрное окно больше не исчезает молча: в скрипте ловушка на любую ошибку + пауза.

Все файлы комплекта кладутся с виндовыми переводами строк; `.ps1` и `.txt` — с меткой
BOM (PowerShell 5.1 без неё читает русский как кашу), `.bat` — без BOM.

## 11. ЕГРЮЛ, лиды, ИИ (кратко)

- **ЕГРЮЛ** (`egrul*.py`): массовое обогащение по ИНН через `@egrul_bot` в отдельной
  вкладке-таблице. Паузы 15–25 с, батч 20, окно 110/сутки. Телефонов бот не даёт,
  но даёт ЛПР по именам.
- **Лиды** (`scan-leads.py`): поиск горячих лидов по сообщениям чатов, карточки в
  «Горячие лиды», отправка в Google-таблицу. Автоскан по таймеру сейчас выключен.
- **ИИ** (`llm.py`): один запрос к OpenAI-совместимому API через curl, настройки в
  `.env` (`LLM_BASE_URL`,`LLM_API_KEY`,`LLM_MODEL`,`LLM_PROXY`).

## 12. Выкладка и проверка

```bash
cd ~/Projects/tg-check && bash deploy/push.sh root@46.16.15.238 --code-only
```

- Копирует код (без данных, сессий, `.env`) и перезапускает `tg-panel`. Автоматика
  после перезапуска продолжает сама.
- **Выкладывать в паузе между задачами:** `pgrep -u tgpanel -fc "python.*\.py"` = 0.
  Иначе оборвётся живая задача (константа: «не сломать прогон на акке Егора»).
- `web/*` читается на каждый запрос — правки интерфейса идут **без перезапуска**; но
  браузер кеширует, поэтому при правке `app.js`/`app.css` поднимать `?v=rNN` в
  `web/index.html` и `web/profiles.html` (сейчас r59).
- Python-задачи проверяются на «песочнице» (подменённый `tglib.connect`) и на
  виртуалке Windows (UTM, `utmctl exec` без экрана) для комплектов.

## 13. Грабли и правила

- Окна `prompt/confirm/alert` замораживают страницу и браузерную автоматизацию.
- `accounts.json` пишут и панель, и задачи — руками править только при остановленной
  панели.
- Один прокси на 19 аккаунтов: всё по очереди, каждому мало времени; нужен второй.
- Время: сервер UTC; «сутки» лимитов от UTC-полуночи (кроме проверок — скользящие 24 ч);
  рабочее время — по Екатеринбургу.
- VLESS-туннель и логику панели трогать обособленно (константа пользователя).
- Старая версия QA-сайта — в `_legacy/`, не трогать без спроса.
